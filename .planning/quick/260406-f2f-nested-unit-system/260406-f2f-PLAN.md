Add a UnitConversion interface and update SupplementItem to support structured units:

1. Add new types after the SupplementTiming section:

```typescript
/**
 * 單位轉換定義
 * 定義一條轉換鏈: 1 baseUnit = factor targetUnit
 * Example chain for fish oil:
 *   { baseUnit: "罐", factor: 100, targetUnit: "顆" }
 *   { baseUnit: "顆", factor: 1000, targetUnit: "mg" }
 * This means: 1 罐 = 100 顆, 1 顆 = 1000mg
 */
export interface UnitConversion {
  /** 來源單位名稱 */
  baseUnit: string;
  /** 轉換倍率 */
  factor: number;
  /** 目標單位名稱 */
  targetUnit: string;
}
```

2. Add to SupplementItem interface:
- `unitConversions?: UnitConversion[]` -- optional array of conversion chain links
- `doseUnit?: string` -- the unit for dosagePerUnit display (e.g. "mg", "mcg", "mL"). When present, dosagePerUnit is displayed as "{dosagePerUnit}{doseUnit}" instead of the raw string.
- `consumptionUnit?: string` -- the unit consumed per dose (e.g. "顆", "粒", "包"). Defaults to "顆" in display if omitted. This is used in inventory tracking.

Keep the existing `dosagePerUnit: string` field unchanged for backward compatibility -- existing data continues to work. The new fields are all optional.

3. Update InventoryEntry to support multi-unit purchases:
- Add `unit?: string` -- the unit of this purchase (e.g. "罐", "顆"). Defaults to consumptionUnit/"顆" if omitted (backward compat with existing data).
